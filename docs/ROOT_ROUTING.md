# TAP 路由实现

TAP 用 SoftEther 核心传输以太网帧。客户端在 Root 下为会话创建独占的 Android TAP 接口，从当前可用的接口编号中选择。首页显示实际接口名。系统的 Ethernet 和 IpClient 处理 DHCP、地址、DNS 及 IPv6 路由。

## 分流流程

1. 连接前选定原 Wi-Fi 或移动网络，校验该网络和所需地址族可用。
2. 从当前配置读取分地址模式及 IPv4、IPv6、CIDR 或精确域名名单。域名通过选定原网络解析为本次连接的地址快照。
3. 分应用模式按 Android UID 生效。相同 UID 的包共用路由。系统网络栈等关键 UID 继续由系统管理。
4. Root 助手为需要绕过的应用或目标应用原网络映射与补充路由，并以会话为单位记录、撤销自己创建的规则。

TAP 地址规则和 TUN 共用配置入口。两种接入方式都依赖服务端现有网关和路由，应用本身不会配置额外 NAT。

## 适用范围

- Root 分流依赖已适配的 Android netd 接口。按 UID 映射要求物理网络具有对应的路由能力，部分仅单栈或 CLAT 叠加接口会被拒绝。
- 应用规则作用于普通新建 IP socket。应用显式绑定接口、选择指定 `Network` 做 DNS、使用隔离进程或收发原始以太网帧时，路由可能由调用方决定。
- 启动时核对旧会话恢复记录。无法确认旧规则已撤销时会停止本次启动，便于检查诊断日志。

排查时优先核对「首页 → 网络详情」的实际接口和地址，以及「日志」中本次会话的地址解析、路由安装和清理记录。接入设置见 [中文 README](../README_zh.md)，原生编译及上游来源见 [原生核心说明](../native-core-source/README.md)。
